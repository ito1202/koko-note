# アーキテクチャ

## 責務

`src/KOKONote.App` はWinForms、トレイ、ホットキー、IME、クリップボードの明示操作、フォーカス、画面内への位置復元、保存先ACLを担当します。`src/KOKONote.Core` はノート、Workspace、保存直列化、DPAPI、SQLiteを担当します。永続化は `INoteStore`、暗号化は `IContentProtector` でのみ差し替え可能にし、DIコンテナーやORMは使いません。

`tests/KOKONote.Tests` はSQLite実ファイルを使う統合テスト、保存競合テスト、純粋なUI判断テストを持ちます。Windowsでは同じプロジェクトにSTAメッセージループを使うGUIテストを追加します。

## 起動・常駐

1. DPIをPerMonitorV2に設定し、ユーザーSIDを含む名前付きMutexを取得します。
2. トレイとメッセージ専用のホットキーHWNDを作成します。`RegisterHotKey` と `MOD_NOREPEAT` を使用します。
3. 保存先のDACLを設定し、`.instance.lock` を排他的に開きます。同じユーザーが別ログオンセッションから同じDBを開くことも防ぎます。
4. UI外でDBを検証・復号します。1件でも失敗すれば保存可能なWorkspaceを作らず中止します。
5. メインフォームを非表示で作成し、初期ノート・状態を保存します。以後は同じフォームを再利用します。

フォームの×はHideへ変換します。明示的な終了時は編集を一時停止し、進行中の保存の後に最新スナップショットを保存します。失敗した場合は終了を中止できます。未保存状態で `WM_QUERYENDSESSION` を受信するとそのシャットダウンを拒否し、非同期保存・終了を試みます。Windowsの終了操作の再実行が必要な場合があります。強制シャットダウンには対応を保証しません。

## 保存の整合性

Workspaceは短時間のlock内で不変レコードを差し替えます。UI編集と保存ワーカーは同じ変更可能なノートを共有しません。入力・名前変更・閉じる・削除は世代番号を増やします。画面状態には別のリビジョンを使います。

保存は `SemaphoreSlim` で直列化します。ゲート取得後にdirtyノートとセッションを撮影し、`Task.Run` 内で暗号化・同期SQLiteトランザクションを実行します。コミット後だけ撮影した世代を保存済みにします。保存中に新しい編集があれば世代差が残り、未保存表示を維持します。キューに待機する保存はゲート取得後の最新状態を使います。SQLにも世代比較を入れ、古い世代によるUPDATEを拒否します。

SQL失敗・暗号化失敗では保存済み世代を更新しません。トランザクションはDisposeでロールバックし、変更と削除待ちの内容はメモリに残ります。成功通知をポップアップ表示しません。再試行のない無限リトライも行いません。

自動保存は500msのWinFormsタイマー1つを編集時に再始動し、Tickの冒頭で停止します。待機時のポーリングはありません。IME編集中はWorkspaceへ未確定文字列を反映せず、変換終了時に反映・保存予約します。既に保存ワーカーが動いていても未確定文字列を撮影しません。

## エディターとセッション

RichTextBoxをネイティブのplain textモードに設定し、貼り付けはUnicodeテキストに限定します。RTF保存、画像、ドラッグによるリッチコンテンツ挿入、URL自動検出を使用しません。既存の開いているタブごとに一度作成した編集コントロールを保持し、Undo/Redo、選択、ネイティブスクロールを保ちます。まだ訪問していないタブのエディターは遅延生成します。閉じたタブのエディターは破棄します。

Ctrl+Wは `IsArchived=true` とするだけで、一覧には残ります。削除は確認を経てtombstoneを作り、次の保存トランザクションでDELETEします。検索は復号済みメモリ上で行います。

`AppState` はアクティブID、ウィンドウの通常位置・大きさ・最大化状態、ノートIDごとの選択範囲・スクロール座標をJSONで保持します。タイトル・本文・検索語を含みません。モニター構成が変わった場合は最大の重なりを持つ作業領域、重なりがなければ先頭の作業領域へ収めます。DPI変更はWinFormsのPerMonitorV2に委ねます。

## スキーマと移行

`Notes` は `Id, EncryptedTitle BLOB, EncryptedContent BLOB, CreatedAt, UpdatedAt, SortOrder, IsArchived, Generation` を持ちます。平文の `Title` 列はありません。`AppState` は単一行です。

`PRAGMA user_version=1` を採用します。空のversion 0 DBだけをトランザクションで初期化します。既存テーブルのあるversion 0と未知のバージョンは拒否します。破棄しての自動再作成や推測による移行は行いません。現時点で既存スキーマへの破壊的変更はありません。今後の移行はSQLite Backup APIで暗号化状態のバックアップを作り、検証後に単一トランザクションで行うことを必須とします。
